
## 1. `axios.ts`

Это не просто "настроенный axios". Это **security boundary** между браузером и Laravel.

Он решает 4 проблемы одновременно:

---

**Единая точка входа**

Весь проект делает запросы только через `api`. Никакого `fetch()` вразброс, никаких отдельных axios instances в разных фичах. Если завтра нужно добавить заголовок или поменять baseURL — меняешь в одном месте.

---

**`withCredentials: true` — без этого Sanctum не работает**

Браузер по умолчанию не отправляет куки на другой домен. `yourshop.com` → `api.yourshop.com` — это cross-origin. Без этого флага session cookie не летит, Laravel видит анонимного пользователя на каждом запросе.

---

**CSRF protection — двухуровневая**

Первый уровень — request interceptor делает prefetch куки **до** мутации. Laravel ставит `XSRF-TOKEN` куку, браузер сам читает её и добавляет `X-XSRF-TOKEN` заголовок к следующему запросу. Ты не трогаешь куку руками — это нативное поведение axios.

Второй уровень — если кука всё же устарела (пользователь оставил вкладку на ночь), response interceptor ловит 419 и делает retry. С дедупликацией — если 5 запросов упали одновременно, за кукой идёт один промис, остальные ждут его.

---

**401 — осознанное решение не редиректить здесь**

Интерсептор только пробрасывает ошибку наверх. Редирект делает `useMeQuery` на уровне компонента. Потому что интерсептор не должен знать о роутинге — это нарушило бы разделение ответственности.

---

## Одна фраза для интервью

> "axios.ts — это security layer. Он обеспечивает cross-origin передачу session cookie, автоматически управляет CSRF токеном Sanctum включая retry при истечении, и централизует обработку auth ошибок не смешивая транспортный слой с роутингом приложения."

# Кейс: Отладка Cookie-Session & CSRF (Next.js + Laravel Sanctum SPA)

## Контекст инфраструктуры

* **Frontend:** Next.js (`localhost:3000`)
* **Backend:** Laravel (`localhost:8000`)
* **Тип сессии:** SPA Cookie-based Auth + CSRF protection.

---

## Пирамида диагностики (Слои отладки)

В кросс-доменной авторизации ошибки валятся строго по цепочке ответственности. Мы двигались снизу вверх:

```
┌─────────────────────────────────────────────────────────┐
│ LEVEL 3: 422 Unprocessable Entity (Бизнес-логика)       │ ◀── Конечная цель. Сеть и безопасность работают.
├─────────────────────────────────────────────────────────┤
│ LEVEL 2: 419 CSRF Token Mismatch / 404 (Безопасность)   │
├─────────────────────────────────────────────────────────┤
│ LEVEL 1: CORS Error (Безопасность браузера)             │
└─────────────────────────────────────────────────────────┘

```

---

## Разбор ошибок и их инженерные решения

### LEVEL 1: CORS Error (PreflightMissingAllowOriginHeader)

* **Суть:** Браузер блокировал ответы от Laravel, так как порты `3000` и `8000` разные (Cross-Origin).
* **Фикс в Laravel (`config/cors.php` и `.env`):**
```php
'allowed_origins' => ['http://localhost:3000'],
'supports_credentials' => true, // Разрешает передачу Cookie/Сессий

```



---

### LEVEL 2: 404 Not Found ➔ 419 CSRF Token Mismatch

После победы над CORS запрос долетал до бэка, но спотыкался о защиту Laravel. Здесь было решено сразу три критических бага:

#### 1. Ошибка путей (404 на куках)

По умолчанию базовый `config.apiUrl` содержал префикс `/api/v1`. Из-за этого запрос улетал на `http://localhost:8000/api/v1/sanctum/csrf-cookie` и возвращал `404`. Sanctum же ждет запрос в корне.

* **Фикс одной строкой:** Удаление префикса через `.replace()` и упаковка в синглтон-промис для защиты от race condition (параллельного спама запросов):

```typescript
// Отрезаем префикс API для получения чистого базового URL бэкенда
const appUrl = config.apiUrl.replace('/api/v1', '');

let csrfCookieRequest: Promise<void> | null = null;

const fetchCsrfCookie = (): Promise<void> => {
    if (!csrfCookieRequest) { 
        csrfCookieRequest = axios
            .get(`${appUrl}/sanctum/csrf-cookie`, { withCredentials: true })
            .then(() => { csrfCookieRequest = null; })
            .catch((err) => { csrfCookieRequest = null; throw err; });
    }
    return csrfCookieRequest;
};

```

#### 2. Фича `withXSRFToken: true` (Секрет Axios 1.6+)

Даже с валидной кукой Laravel продолжал отдавать `419`.

* **Причина:** Раньше Axios автоматически читал куку `XSRF-TOKEN` и сам ставил заголовок `X-XSRF-TOKEN` только для *same-origin* запросов. Для *cross-origin* (`localhost:3000` ➔ `localhost:8000`) теперь **обязателен** явный флаг в конфиге Axios:

```typescript
axios.defaults.withXSRFToken = true; // Заставляет Axios слать заголовок на сторонний порт/домен
axios.defaults.withCredentials = true; // Разрешает принимать куки от бэкенда

```

#### 3. Перевод Laravel в режим Stateful

Маршруты авторизации перенесены в `routes/web.php` (или обернуты в мидлварь `EnsureFrontendRequestsAreStateful`), чтобы Laravel инициализировал сессию PHP и сверял тот самый заголовок `X-XSRF-TOKEN`.

---

### LEVEL 3: 422 Unprocessable Entity (Победа)

* **Суть:** Появление ошибки `422` вместо `419` — маркер триумфа. Это означает, что вся цепочка (CORS, Кросс-доменные Куки, CSRF-заголовок, Сессия) отработала идеально. Laravel пустил запрос внутрь, дошел до слоя валидации (`FormRequest`) и вернул понятные ошибки бизнес-логики (например, "Неверный пароль").

## Как это красиво звучит на интервью

> *"Я настраивал авторизацию на куках между Next.js и Laravel Sanctum в кросс-доменном режиме. Столкнулся с классической цепочкой блокировок: от CORS до CSRF (419 ошибка).*
> *Проблему CORS решил через `supports_credentials` в Laravel. Ошибку `419` победил комплексно: во-первых, отрезал префикс API `/api/v1` для правильного запроса к `/sanctum/csrf-cookie`. `XSRF-TOKEN` — это НЕ токен авторизации.

**CSRF/XSRF-токен вообще не знает, кто ты такой — гость или залогиненный админ.**

У него только одна задача — **безопасность (защита от дурака и хакера)**. Он доказывает серверу, что запрос пришел именно с твоего доверенного фронтенда (`localhost:3000`), а не с левого фишингового сайта, который пытается втайне отправить форму от твоего имени.

## Как на самом деле работает связка в Sanctum SPA

Под капотом работают **два абсолютно разных механизма одновременно**:

### 1. Механизм Личности (Кто ты?) — `laravel_session`

* **Что это:** Обычная, классическая **сессия PHP**.
* **Как передается:** Бэкенд ставит куку с именем `laravel_session` (в ней зашифрован ID сессии). Браузер автоматически прикрепляет эту куку к **каждому** запросу на бэк.
* **Суть:** Laravel смотрит на `laravel_session`, лезет в свое хранилище (Redis/файлы/БД), находит сессию и говорит: *«Ага, этот запрос шлет юзер с ID = 5»*.

### 2. Механизм Защиты (Безопасно ли?) — `XSRF-TOKEN`

* **Что это:** Анти-подделочный токен.
* **Как передается:** 1. Когда ты делаешь `GET /sanctum/csrf-cookie`, Laravel присылает куку `XSRF-TOKEN`.
2. Твой Axios (благодаря `withXSRFToken: true`) читает эту куку, копирует её значение и вставляет в **заголовок** (`Header`) следующего запроса под именем `X-XSRF-TOKEN`.
* **Суть:** Laravel берет куку `XSRF-TOKEN` и заголовок `X-XSRF-TOKEN`. Если они совпадают — значит, запрос отправлен через твой Axios, доступ к кукам есть, всё чисто. Если заголовка нет или он не совпадает — получай `419 CSRF Token Mismatch`.

## Итоговый Lifecycle (Запрос / Ответ) в одном куплете

Когда ты жмешь «Войти» с правильными данными:

1. **Request (Фронт $\rightarrow$ Бэк):** * Передаются куки (включая `XSRF-TOKEN`).
* Передается заголовок `X-XSRF-TOKEN` (проверка безопасности).
* Передаются `email` и `password`.


2. **Бэкенд проверяет:** Безопасность пройдена? Да (заголовок совпал). Пароль верный? Да.
3. **Response (Бэк $\rightarrow$ Фронт):**
* Laravel генерирует сессию для этого юзера.
* Возвращает заголовок `Set-Cookie: laravel_session=XXXXXX...`


4. **Следующий запрос (например, на `/me`):**
* Браузер автоматически шлет куку `laravel_session`.
* Laravel видит её, узнает тебя и отдает `200 OK` с твоим профилем.



---

## Железобетонное резюме для памяти:

* **Сессионная кука (`laravel_session`)** — отвечает за **Аутентификацию** (говорит Laravel, *кто* ты).
* **CSRF-кука и заголовок (`X-XSRF-TOKEN`)** — отвечают за **Безопасность** (говорят Laravel, *откуда* пришел запрос).
